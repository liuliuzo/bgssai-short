# 图生视频（image-to-video）

## 一、背景与目标

- 背景：创作台已有「构图OK，生成视频」，那是文生视频。创作者还需要用一张已有图片加提示词生成短视频。
- 目标：上传或选择图片，填写提示词，走独立的图片条件调用，异步查看状态，完成后预览和下载，原图仍在。
- 关联角色：`USER`。成片播放仍在 Tube，本仓不重做播放器。
- 当前真实服务契约是 `v0.2-validated-20261111-1137Z`。供应商已用真实 API 产出一条技术可解码的成片：384×256、25 帧、8 fps、3.125 秒，墙钟 1258 秒，CPU 并发 1。本仓没有打到该服务，也没有浏览器端到端验收。画面观感由父级看片。

## 二、需求澄清（WHAT）

- 用户故事一：作为 `USER`，我希望上传 PNG 或 JPEG，或选用镜头首帧，加上提示词后提交图生视频。
- 用户故事二：作为 `USER`，我希望服务未就绪时看到「暂不可用」，原来的文生视频仍可使用。
- 用户故事三：作为 `USER`，我希望完成后同时看到原图和标成 AI 生成的结果，失败不扣费。

- 业务规则：
  1. 图生视频是 `target_type=IMAGE_TO_VIDEO`，不复用镜头「生成视频」按钮，也不把图片写进文生视频提示词。
  2. 未启用、密钥为空或没有批准的可达地址时，能力接口 `available=0`，提交返回 `4014`。不模拟成功。
  3. 图片只认 PNG / JPEG 魔数。超过 8MiB 或 16000000 像素拒绝。服务端 v0.2 对超过 16000000 像素返回 HTTP 400。不按浏览器声明的类型放行。用户不能提交图片 URL，应用只读已归属的存储对象。
  4. 宽 128-384、高 128-256，且为 32 的倍数；帧数 9 / 17 / 25 / 33；帧率 1-24；步数 10-30；提示词 1-2000。缺省 384×256、25 帧、8 fps、20 步、种子 42。超出范围拒绝，不悄悄改小。
  5. 时长按帧数除以帧率计算。界面不承诺高清或任意时长。
  6. 供应商没有幂等键、取消和 TTL。应用用 `client_request_id` 认出同一次提交。提交结果不确定时保留原任务，不自动再提交。
  7. 全局同时只跑一笔图生视频。供应商忙返回应用侧 `429000`。
  8. 每个阶段最长 7200 秒，编码加推理按 14400 秒封顶。轮询间隔升到 15 秒后保持，覆盖已观测的约 21 分钟。状态查询可能是 HTTP 200 且 `failed`。只有完成态才取成片；v0.2 在完成前取内容返回 409。
  9. 成片先做媒体校验再入库。校验失败不扣费。成功只结算一次。种子单价为 0，不另造价格。
  10. 用户看到的模型名是 BGSSAI Video / `bgssai-video`。响应不带供应商错误、指标、任务号或上游技术名。结果 `ai_generated=1`。
  11. 素材、任务和下载都校验归属。已定稿镜头可以生成素材，但不改写该镜的视频和状态。
  12. 模型行只在 `sql/dev/DML.sql`，默认关闭、没有 base_url。不写生产种子，不写可调用的假地址。以后由管理端把专用网关源站写入该模型行。应用回环，以及模型机公网或内网地址的 8007 端口，仍然拒绝。其它管理端源站可以接通。用户请求不能改这个地址。

## 三、验收标准

1. 能力关闭时创作台图生视频区显示不可用，提交按钮不可用，文生视频按钮仍在。
2. 超限图片、超范围宽高或帧数被拒绝，请求值不被改成默认值。
3. 同一 `client_request_id` 与相同图片参数返回原任务；参数不同被拒绝。
4. 已有进行中的图生视频时，新提交返回忙碌。
5. 失败、超时和结果不确定都不扣费，也不自动改走文生视频。
6. 别人的图片、镜头、任务和下载不能访问。
7. 供应商技术成片已存在。本仓浏览器端到端仍未验收：没有批准的跨主机地址，开发种子不启用、不写地址，也没有可访问的新版本。本条未完成。
