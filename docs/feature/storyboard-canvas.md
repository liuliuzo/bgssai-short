# 分镜画布编排（storyboard-canvas）

## 一、背景与目标

- 背景：分镜工作台现在是一列纵向卡片。一集四五十镜，要看完整集得滚十几屏，结果是
  **看不见全貌**：哪几场还停在文字层、哪几镜卡在草图、哪一段已经全是视频了，脑子里拼不出来。
  批量操作也只能靠一个个勾选，勾到第三十个就乱了。创作者真正想做的两件事——
  「整集扫一眼现在到哪了」和「把这一段十几镜一起重跑」——列表都不擅长。
- 目标：整集在一屏内看完，按场次分行、按镜号排列，颜色即状态；框选一段即可整组估费用、整组提交；
  顺序拖得动。
- 关联角色：`USER`。

## 二、需求澄清（WHAT）

- 用户故事一：作为 `USER`，我希望一眼看出整集哪些镜头到了哪一步，不用滚屏拼记忆。
- 用户故事二：作为 `USER`，我希望框住一整场戏的镜头，一次性估费用、一次性重跑。
- 用户故事三：作为 `USER`，我希望能把某一镜往前挪两个位置，而不是回剧本层重新拆镜。
- 用户故事四：作为 `USER`，我希望在画布上点开一镜就能改它的人话分镜，改完不用切回列表。

- 业务规则：
  1. **画布是第二视图，不是替代**：分镜工作台保留列表视图（适合逐镜精改文字，并在已有
     `video_url` 时直接播放；没有视频时首帧和尾帧可点击放大）。画布不是唯一播放入口。新增画布视图
     （适合看全貌与批量操作），顶部切换。两个视图读写**同一份数据、同一套接口**，
     不产生第二套状态——两个视图各存一份就是必然漂移。
  2. **布局由数据算出，不存自由坐标**：节点位置 = 场次（行）+ 镜号（列），由 `scene_no` 与
     `shot_no` 推出，**不提供自由拖到任意位置**、也不落任何坐标字段。理由：自由坐标会成为
     第二份「顺序」事实，与 `shot_no` 必然对不上；而创作者拖动节点的真实意图是**改顺序**，
     不是改布局。把拖动直接解释成改顺序，比存一份坐标更贴近他要做的事。
  3. **节点承载的信息**（一眼可读，不需点开）：镜号、时长、缩略图（当前级别素材）、
     状态色、当前预演级别、是否被阻断、是否 stale。
  4. **状态色口径**（与列表视图同一套语义，不另发明）：
     `PENDING` 灰 / `TEXT_READY` 蓝 / `DRAFT_READY` 浅紫 / `IMAGE_READY` 青 /
     `VIDEO_READY` 绿 / `LOCKED` 深绿 / 失败或阻断 红 / `stale_flag=1` 描橙边。
  5. **框选批量**：鼠标拖拽框选多个节点，或点节点加选。批量操作复用既有接口
     （`/ai-tasks/estimate` 与 `/ai-tasks/submit`），**先出费用再提交**，与列表视图完全一致的
     预算闸门口径——画布不是绕过预算确认的后门。
  6. **拖拽重排**：把节点拖到同场次内另一位置即改 `shot_no`，整场重新编号（连续、无空洞）。
     重排**只改顺序**：不删素材、不改状态、不触发任何重抽。
  7. **跨场拖拽不允许**：节点只能在本场次行内移动。跨场移动意味着这一镜换了场景，
     那是剧本层的事（回剧本改场次划分再拆镜），在画布上硬拖会让镜头的 `scene_no` 与它的
     画面内容、场景卡对不上。界面上跨场拖动直接不吸附，并给出提示。
  8. **重排的下游影响**：重排后，凡 `frame_link_mode=INHERIT_PREV` 且上一镜发生变化的镜头
     置 `stale_flag=1`（复用 `frame-continuity.md` 的机制），页面提示「上一镜变了，可能接不上」，
     **不自动重抽**。
  9. **锁定镜头不参与重排**：`shot_status=LOCKED` 的镜头在画布上显示锁标记、不可拖动，
     与列表视图的锁定语义一致。
  10. **画布不做无限缩放与自由连线**：只提供适应宽度与 1:1 两档缩放；不画节点间连线——
      镜头顺序由左右位置表达已经足够，连线只是把「一条直线」画成图，占地方且没有新信息。

## 三、验收标准

1. 一集 44 镜、7 个场次，画布视图内 7 行排布，一屏可见全部镜头与各自状态色。
2. 列表视图改了某镜的人话分镜并保存后，切到画布视图该镜内容同步（同一接口读取，无第二份状态）。
3. 框选第 3 场的 8 个镜头，点「估费用」返回 8 镜合计费用；点「批量生成」按该费用提交，
   与列表视图勾选 8 镜的结果逐字一致。
4. 把镜 12 拖到镜 9 的位置，本场次重新编号为连续序列，其余场次镜号不变；已生成素材与状态不变。
5. 跨场次拖动不生效，给出「跨场请回剧本层改场次划分」提示。
6. 重排后，开启了「接上一镜」且上一镜发生变化的镜头出现 stale 标记，且系统不自动提交任何任务。
7. `LOCKED` 镜头显示锁标记且拖不动。
8. 画布与列表切换后当前选中集与筛选条件保持不变。

## 四、接口契约（snake_case）

- `POST /bgssai/user/shots/reorder`
  ```json
  { "episode_id": "e-20001", "scene_no": 3, "shot_id_list": ["s-40012", "s-40009", "s-40010"] }
  ```
  按数组顺序重排该场次镜号（从该场次最小镜号开始连续编号）。
  响应 `{ "result": { "reordered_count": 3, "stale_shot_no_list": [13] } }`
- 画布其余数据与操作**不新增接口**，复用：
  `GET /bgssai/user/shots/list?episode_id`（含 `scene_no`、`shot_no`、`shot_status`、
  `previz_level`、`first_frame_url`、`video_url`、`stale_flag`、`blocked_flag`、`frame_link_mode`）、
  `POST /bgssai/user/ai-tasks/estimate` · `/submit`、`POST /bgssai/user/previz/save`。
- 鉴权：需 `Jwttoken`；错误码：`50000001` 参数非法（镜头不属于该场次 / 列表为空）/
  `4003` 越权 / `4006` 含锁定镜头不可重排 / `429000` 限流。

## 五、流程 / 状态机（须配图）

画布视图的布局推导、批量选择与重排规则见 [`flow-storyboard-canvas.html`](./flow-storyboard-canvas.html)。
本功能不引入新状态机：镜头状态、预演级别、锁定语义全部沿用 `storyboard-workbench.md` 与
`previz-text-storyboard.md`。

## 六、数据模型影响

- **不新增表、不新增列**。画布布局全部由既有的 `scene_no` / `shot_no` 推导；重排改的是
  `short_shot.shot_no`。这是本功能刻意的设计——一旦为画布存坐标，就多出一份与镜号并行的顺序事实。
