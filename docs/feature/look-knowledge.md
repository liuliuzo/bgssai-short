# 定妆库、场景库与道具库

## 一、背景与目标

定妆与场景参考不能只靠模型每集重画。创作者可以上传或归档自己的角色造型、场景参考、道具图片或一段参考视频，直接锁定为当前作品的参考图，也可以在跨剧集、跨作品创作时统一管理与复用，生成候选和分镜画面时作为一致性参考。

## 二、需求澄清

- 用户故事：作为创作者，我上传一张自己的图片，锁定后全剧按这张图保持形象。
- 用户故事：作为第一次做短剧的创作者，我在角色卡上就能上传照片，或从定妆库里点选一个已有造型，生成前能看见将要用的那张参考图。不用先离开作品，也不用靠名字去猜。
- 用户故事：作为创作者，我把角色造型、场景参考和道具参考分别放进定妆库、场景库和道具库，也可以放一段参考视频。生成该角色或场景的候选时，系统按名称和说明选出最接近的一张，交给图像模型作主体参考。视频用它的一帧画面。名称对上只是兜底，页面会写明将用哪一张，也可以改成这次只按文字生成。
- 业务规则：
  1. 图片接受 JPG、PNG、WebP，视频接受 MP4，都最大 6MB。
  2. 角色定妆照分四面：正脸、前面、背面、侧面。正脸上传后立即锁定，作为全剧生成时交给模型的那一张，并成为这张卡当前选中的图。另外三面保存在这张角色卡和定妆库里。场景库按全景主图、中景机位、局部陈设三个机位组织（优先使用全景主图）；道具库按主视图、特写细节两个视角组织（优先使用主视图）。在作品场景卡和道具卡上上传照片后自动锁定，并归入对应主机位或主视图；已选定的生成图也可以点「存入场景库」「存入道具库」「存入定妆库」一键归档。
  3. 定妆库（`/look-library`）、场景库（`/scene-library`）分别提供独立导航和页面，道具库（`/prop-library`）保留为独立入口。每页固定一种素材类型，仅显示该类型的数量、卡片、上传格位与新建文案，不再使用合并库名称，也不再在一个页面切换三类素材。作品内的管理入口直接进入对应页面；旧 `/look-library?kind=SCENE` / `?kind=PROP` 链接自动转入对应独立页并保留安全的返回路径。已有素材仍按 `material_kind` 分类，不迁移或删除数据。
  4. 现有知识库作为跨类型的素材分组保留，角色卡、场景卡、道具卡上的照片仍自动归档至「我的定妆」分组。页面的新建操作称为「新建分组」，左侧列表只统计当前页面所属类型的数量。分组的自动匹配开关、归档恢复仍作用于该分组的全部素材；当分组含其他类型时，页面明确提示，避免误以为只影响当前页面。各分类之间切换页面时，输入草稿、上传目标及弹窗不串用。
  5. 在角色、场景、道具卡上可以展开对应分类素材库，看见造型、场景或道具封面图，点「用这个造型」「用这个场景」「用这个道具」后，这张卡锁定该条目主图。同一条目仍留在库里，别的剧集和作品还能再用。
  6. 点「生成定妆」或「生成参考图」之前，页面写明这次会用哪一个分组、哪一个条目；没有参考图时写明只按外观描述生成。已选定的条目优先于按名称对上的图。名称对上至少 3 个字，或名称被描述包含，才作为兜底参考，并在页面上标明。勾选「这次不用参考图」后，这一次只按文字生成。命中视频时，用该视频的一帧画面。
  7. 上传不扣模型费用。生成候选仍按原价确认。
  8. 定妆库页把一个造型的正脸、前面、背面、侧面排在同一行，四个格子一样高。没有照片的那一面写明「这一面还没有照片」，旁边可以上传这一面。点任何一张照片都能看大图，同一面的第二张、第三张也一样。照片地址打不开时，格子里写明「这张照片没有加载出来」，可以移除。
  9. 同一面如果有多张照片，上面只放大最新的一张。更早的照片改到这一行下面，按角度排开，不把四个格子挤乱。生成时仍优先用正脸那张主图。
  10. 参考视频不和定妆照一样大，单独放在「参考视频」里。封面只是视频里的一帧，人在动的时候这一帧会发糊或切得很近，所以不当成定妆照。点开可以播放，也可以移除。不删除用户另外上传的正常照片。新上传的视频会多截几帧，挑更清楚的一帧当封面。
  11. 同一张照片放进多个角色卡时，库内只显示一次。移除这张时，重复的那一份一起拿掉，其他不同的照片还留着。
  12. 说明里写明了角度时，按正脸、前面、背面、侧面归位。没写角度、又没指定格子时，不再一律塞进正脸。站姿、坐姿、行走是补充：这一面已经有一张普通照片时，补充的放到「其他照片」，不占主位，也不拿来冒充缺的那一面。
  13. 有正脸之后，空着的前面、背面、侧面可以「按正脸生成」；已经有照片的可以「按正脸重做」。一次会把正脸照片交给图像模型，并要求还是同一个人、同一张脸、同一套衣服。生成前写明要画哪几面和预计费用，确认后才出图。正脸本身不拿来再生成一张正脸。模型不能保证每张都完全锁死，走样了可以再重做。角色卡上同样可以按这张角色的正脸补面。

## 三、验收标准

1. 角色卡上传正脸后，定妆页显示这张照片，状态为已定妆，当前选中的也是这张，不再停在旧的生成图上。
2. 同一张图进入「我的定妆」分组。分组不存在时自动创建，创作者不用先去建分组。
3. 定妆库页管理可复用造型。从角色卡进来可以返回角色与场景。分组里没有角色时，说明去角色卡上传或直接在当前页添加即可。
4. 在角色卡上点选一个造型后，生成前能看见将使用的分组名和造型名。没有对上的参考图时，写明这次只按外观描述生成。勾选后，这一次不附带参考图。
5. 定妆库页点开正脸、前面、背面、侧面以及同一面多出来的照片，都能看到大图。没有照片的那一面是写明「这一面还没有照片」的空位。参考视频单独小图放在下面，点开播放，不和定妆照一样大。
6. 有正脸时，空位可以按正脸生成前面、背面或侧面；已有的面可以按正脸重做。确认费用后，新照片进入对应角度。侧面和背面的请求带着正脸参考图，并写明衣服和人不要换。
7. 桌面导航和手机「更多」分别显示「定妆库」「场景库」「道具库」，页标题与导航一致，无合并库名称和跨类型切换按钮。场景页只显示「全景主图 / 中景机位 / 局部陈设」，道具页只显示「主视图 / 特写细节」；作品卡的管理链接直达对应页面，安全返回路径保留。新建、上传和删除均针对当前分类素材，现有分组级设置的跨类型作用有明确提示。

## 四、接口

- `GET /bgssai/user/look-libraries/list`
- `POST /bgssai/user/look-libraries/save`
- `POST /bgssai/user/look-materials/upload`
- `POST /bgssai/user/look-materials/delete`
- `POST /bgssai/user/look-materials/complete-angles`

`complete-angles` 的 Body：`library_id` + `material_name`，或 `character_id`。可选 `view_angle`（前面 / 背面 / 侧面；不传则补齐缺的这三面）、`replace_existing`（1 表示这一面已有照片也重做）、`model_code`、`confirm_cost`。`confirm_cost` 不是 1 时只返回 `angle_list`、`angle_name_list`、`estimated_cost_cent`，不出图。确认为 1 时排队一张图片任务，返回 `task_id`、`batch_id`。侧面和背面（以及前面）都会带上正脸的 `image` 参考。
- `POST /bgssai/user/characters/portrait-upload`
- `POST /bgssai/user/characters/apply-look`
- `POST /bgssai/user/scene-cards/portrait-upload`
- `POST /bgssai/user/scene-cards/apply-look`

角色列表、场景列表和一致性面板的每张卡带回 `look_reference`：`used`、`source`（`CARD` 已选定 / `NAME` 名称对上 / `NONE` 没有）、`library_name`、`material_name`、`view_name`、`file_url`。生成请求可带 `skip_look_reference=1`，只对这一次生效。

列表里每条素材带回 `width`、`height`、`file_size_byte`。页面用这三项认出同一张照片的重复条目，只显示一次。

鉴权需 `Jwttoken`，只操作当前用户自己的分组和卡。
