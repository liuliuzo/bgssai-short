# 已提交视频的恢复

网关已经接收公司视频任务，但后续查询失败时，本地任务不能通过恢复按钮再次提交生成。恢复仅适用于本人 FAILED/CANCELED 的 bgssai-video 镜头任务：本人同作品、同任务、同模型必须存在唯一持久用量回执，镜头还没有视频、未锁定且没有后续/其他活动视频任务。否则拒绝，不能猜测上游任务。

现有 ai-tasks/recover 对公司视频采用此恢复路径；其他任务保持原行为。MCP 新增 resume_video_task(task_id)，不接受上游 ID、URL、用户、回执或模型覆盖。仍是正式队列、媒体校验、资产存储与原任务结算；不再次 POST 生成，不新建回执，不表示原任务免费。

恢复时必须保留原回执 endpoint、密钥指纹和模型，密钥轮换或跨环境时明确拒绝，不用另一凭据尝试。使用回执 request_id 查询网关已有任务，未知/不唯一/越权/已失败均拒绝，不回退重新生成。并发恢复同一任务只有一次能重新入队。新生成视频的提示词应同时保留画面描述和额外风格，不能因额外提示词存在而丢失剧情。

不新增表或 SQL 字段，不手工修任务状态；实际旧任务恢复与最终MP4须发布后另行验收。

恢复等待期间镜头可能被修改、锁定、选择新视频或创建后续视频任务。恢复结果先保存为未选候选，落镜前重新核对归属、镜头版本与后续任务，并由数据库条件更新确认镜头仍保持原状态且没有视频。并发条件不满足时明确拒绝落镜，保留未选候选，不覆盖新结果。视频资产时长始终保留实际媒体解析结果，不能用分镜计划时长覆盖。

更新时间仅有秒精度时，仍必须比较镜头版本与提示词版本；同一秒内编辑导致任一版本变化也拒绝旧恢复结果落镜。

公司视频同一时间只准入一条。还没轮到的保持排队中，并写明前面还有几条，以及通常每条约十多分钟、一次只生成一条。正在生成的显示已等待时间，不再停在 30%。网关超时（504000）或调用中断时，若原回执仍在，任务保持未完成，按原来的 request_id 继续查询，不新开生成、不二次计费。种子 SVG、没有成片的占位素材不能记成视频已完成，也不能当作首帧或定妆参考。

公司视频的提示词先写已锁定角色的外貌和服装、场景和道具，再写这一镜的动作。有真实定妆照片或真实首帧时，作为参考图提交。首帧和定妆都还是占位图时，不提交生成，并说明要先换成真实照片。
