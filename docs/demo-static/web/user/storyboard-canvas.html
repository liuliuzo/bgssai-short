拖动就是改顺序

把节点拖到本场次内另一个位置，就是改镜号，整场重新连续编号。 重排只改顺序：不删素材、不改状态、不触发任何重抽。
跨场拖不动——跨场意味着这一镜换了场景， 那是剧本层的事（回剧本改场次划分再拆镜）。在画布上硬拖，只会让镜头的场次号 和它的画面内容、场景卡对不上。
不存自由坐标：位置由场次与镜号算出来。 存了坐标就多出第二份「顺序」事实，它和镜号迟早对不上；而你拖动节点的本意本来就是改顺序。

框选批量，费用照旧先算

拖拽框住一整场，或点节点加选。批量估费用、批量提交走的是 和列表视图完全相同的接口与预算闸门，结果逐字一致。
画布不是绕过费用确认的后门——两个视图只是看法不同， 不是两套逻辑。

字段口径
画布不新增数据：节点位置由 scene_no（行）与 shot_no（列）推出， 不落坐标字段、不新增表。 数据来自 GET /bgssai/user/shots/list?episode_id （scene_no · shot_no · shot_status · previz_level · first_frame_url · video_url · stale_flag · blocked_flag · frame_link_mode）。 批量操作复用 POST /bgssai/user/ai-tasks/estimate 与 /submit； 单镜编辑复用 POST /bgssai/user/previz/save。 唯一新增接口是重排：POST /bgssai/user/shots/reorder （episode_id · scene_no · shot_id_list， 返回 reordered_count 与 stale_shot_no_list）。 LOCKED 镜头不可拖动；含锁定镜头的重排返回 4006； 镜头不属于该场次返回 50000001。 需求见 storyboard-canvas.md。
